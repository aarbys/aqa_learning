# 🧪 Automated Quality Assurance (AQA) Learning Project

Это **учебный репозиторий**, созданный для отработки навыков автоматизации тестирования API на языке Python. Цель проекта — построение гибкого, масштабируемого и независимого фреймворка автотестов с нуля.

В ходе работы над проектом были реализованы ключевые паттерны автоматизации (API-клиенты, разделение логики тестов и конфигурации, валидация контрактов данных).

---

## 🏛️ Архитектура и устройство проекта

Проект спроектирован по классической многослойной структуре, что позволяет легко изолировать логику запросов от самих проверок:

```text
aqa_learning/
├── api/          # Слой HTTP-клиентов и методов взаимодействия с API
├── models/       # Слой валидации (контракты данных / схемы ответов)
├── tests/        # Слой тест-кейсов (тестовые сценарии)
├── config.py     # Централизованная конфигурация и управление окружением
└── conftest.py   # Фикстуры Pytest (управление сессиями, авторизация, setup/teardown)
```

### 🔍 Что именно реализовано и изучено в проекте:

1. **Изоляция API-логики (`api/`):**
   * Создан базовый HTTP-клиент на основе библиотеки `requests`, автоматически обрабатывающий заголовки, логирование запросов/ответов и сессии.
   * Логика запросов вынесена в отдельные классы (API-хелперы), что исключает дублирование URL-адресов и параметров в тестах.

2. **Валидация контрактов (`models/`):**
   * Реализован подход **Schema Validation** (валидация схем ответов). С помощью моделей (Pydantic или dataclasses) проверяется не только статус-код, но и структура JSON, типы полей, а также обязательное наличие ключевых параметров. Это защищает тесты от незаметных изменений со стороны бэкенда.

3. **Организация тест-кейсов (`tests/`):**
   * Написаны позитивные сценарии (проверка бизнес-логики) и негативные проверки (обработка ошибок 4xx/5xx).
   * Использован фреймворк `pytest` с применением параметризации (`@pytest.mark.parametrize`) для прогона тестов на различных наборах данных без дублирования кода.

4. **Управление конфигурацией (`config.py` и `conftest.py`):**
   * Вынесена настройка базовых URL и конфигурационных параметров (Config as Code).
   * Написаны переиспользуемые фикстуры (fixtures) для автоматического создания/удаления тестовых сущностей (Clean Up), генерации динамических данных перед тестами и передачи авторизационных токенов.

## 🛠️ Технологический стек

* **Язык:** Python 3.10+

* **HTTP-клиент:** Requests
* **Валидация:** Pydantic / Data Models
* **Зависимости:** `requirements.txt` (управление пакетами через pip) и `pyproject.toml`

## 🚀 Локальный запуск тест-кейсов

Чтобы развернуть проект и запустить тест-кейсы на локальной машине, выполните следующие шаги в терминале:

### 1. Подготовка окружения
Склонируйте репозиторий и перейдите в его корневую папку:
```bash
git clone https://github.com/aarbys/aqa_learning
cd aqa_learning

```

### 2. Активация виртуального окружения
* **Windows (PowerShell):**
  ```bash
  python -m venv .venv
  .venv\Scripts\Activate.ps1
  ```
* **Linux / macOS:**
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  ```

### 3. Установка зависимостей
Установите все необходимые для работы фреймворка библиотеки:
```bash
pip install -r requirements.txt
```

### 4. Запуск тестов
Для прогона тест-кейсов используйте команды `pytest`:
* **Запуск всех тестов:**
  ```bash
  pytest
  ```
* **Запуск с подробным выводом (verbose режим):**
  ```bash
  pytest -v
  ```
